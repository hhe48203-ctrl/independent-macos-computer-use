## Known limitations with public APIs only

With `--public-api-only`, the following routes have no verified background delivery that leaves the user undisturbed. The driver never reports them as background successes. Routes it can identify before dispatch are rejected with a reason. Routes it cannot identify in advance return an error once a reorder or focus loss is detected, and the benchmark then stops input for that trial. These limitations do not relax GUI-only or A22 and never switch to the foreground automatically.

Upstream reference: trycua's [Cua Driver Bench post](https://cua.ai/blog/cua-driver-bench) lists two open macOS gaps, a popup menu shown over the user's window for about 50 ms while choosing a value, and background drag (MB-09 0/5). The same post reports that cua-driver keeps a background app's sheet behind the user's window on macOS. The IR-01 sheet reordering is therefore a limitation of this repository under the public-API constraint, not a shared upstream problem. As of 2026-11-14 the three related PRs are unmerged. [#7497](https://github.com/trycua/cua/pull/7497) refuses background popups and context menus when a raise cannot be avoided. [#7567](https://github.com/trycua/cua/pull/7567) adds type-select on top of it, which works only when the app counts itself active (`AXFrontmost`) and otherwise refuses. This matches the unchanged value after first-letter input on `147201` here. [#7556](https://github.com/trycua/cua/pull/7556) completes background drag with a shield panel and one hardware mouse down and up at the user's pointer, and its author notes that the WindowServer behavior it relies on is not a documented contract. This repository does not adopt such routes.
